# 从现象到证据的排错顺序

1. 无串口：核对电源、实际枚举号、数据线与接口；JTAG 能连接不说明 PL UART 已工作。不要因枚举故障修改算法。
2. 响应被拒绝：保存原始 TX/RX，逐项查 magic、长度、版本、命令、序号、CRC，再比较载荷。A4 曾出现结果内容正确但响应类型沿用旧值；严格解析发现并阻止继续验收。
3. 仿真提前停止：查 PASS/FAIL、$finish/$fatal、超时字面量单位与位宽；编译成功或退出码 0 均不能代替功能通过。A2 的超时常量曾截断。
4. 仿真与综合不同：查语言模式、BRAM 同步读延迟、数组复位、DSP 位宽及字节写；必要时做综合后功能仿真。A5 的 .v 文件曾使用 SystemVerilog 循环变量声明。
5. 结果一致但太慢：先拆完整调用的搬运、计算、读回与判决，再移动真正的瓶颈。保留同任务同输入的旧路径，不拿不同算法/容量的运行时间直接比倍数。
6. 复位后偶发错误：核对当前版本，清除控制/有效标志，重载输入；BRAM 无需整阵列复位。按键、仿真复位与重下载分别记录，不互相替代。
7. 数据重放全对但应用效果不佳：计算一致性只证明实现遵循算法。把真值命中、漏检、额外输出、容量边界和误报分组统计，保留失效样本，不回改阈值或删样本美化统计。

流程仅涉及检查。任何重新下载、Flash 写入、改变供电接线或公开数据仍须遵守使用者原任务与硬件约束。
