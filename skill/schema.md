# 数据契约

每行 JSON 表示一个唯一 case_id，文件编码为 UTF-8。黄金文件示例：

```json
{"case_id":"dot_001","input_sha256":"填入实际输入字节的64位小写sha256","result":-16}
```

实测文件多一个 `build_id` 字段。`result` 可以是整数、null、数组或嵌套对象；数组顺序有意义，因此需要输出无序集合的题目须在独立适配器中按预先定义的规则规范化。不得为掩盖错误临时排序。

输入哈希应覆盖完整输入字节和影响算法的参数，如 N、系数、阈值、定点格式；黄金端和实测端约定同一序列化格式。仅对文件名取哈希没有意义。重复 case_id、缺少或新增 case、版本不符、输入不符、结果不符均拒绝。期望无输出可表示 `[]`；未执行的软件路径不可伪造为已测结果。

文件清单格式为 `{"sha256":{"relative/file.ext":"64位摘要"}}`。路径以被核验根目录为准，不接受路径越界；本工具只验证清单内文件，不自动认定清单外文件可以提交。

计时文件为 `{"trials":[...]}`。每项必需：task、case_id、input_sha256、build_id、clock_hz、boundary、mode、cycles。所有项前六字段必须完全一致；boundary 固定为 board_full_task；mode 为 cpu 或 accelerator，cycles 为正整数。每种模式重复数量相等。输出中位数与完整调用加速比，不估计 P99。

测量规范：CPU 与硬件完成同一算法；CPU 编译优化、输入范围和边界规则写明；完整硬件调用包括必要搬运、配置、轮询与结果读取。CRC、额外参考核对和 UART 是否包含在计时中必须在插桩前确定。本工具接受声明，不能通过数字本身证明声明正确。
