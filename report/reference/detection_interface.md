# A2 检测接口与复现

版本 `0000A201`，目标 `xc7z100ffg900-2`，50 MHz，Vivado 2023.1。算法沿用 [A1 冻结规则](improvement_a_plan.md)。本文件定义接口；实际验收状态见 A2 验证记录。

## 数据流

电脑通过 PL UART 发送一帧 64–1024 点的 int16 数据，检测模式只接受 -2048–2047。CPU 在自有 BRAM 中保留输入，执行软件参考，然后向扫描器搬运一次整帧。扫描器中的模板首次加载 64 次，后续帧复用，复位后重新加载。

扫描器对每个起点读取板内帧缓冲的 64 点，用模板符号做加减，产生相关和 S；首窗口累加平方能量，后续窗口用前窗口能量减去离开样本的平方，加上新样本平方。核心每窗口 66 周期，包含读取和流水线排空。它复用板内存储，仍为每个窗口读取 64 点；没有宣称每样本只访问一次或每周期产生一个窗口结果。

RISC-V 逐个读取 S/E，使用 uint64 交叉相乘选峰；阈值、最早并列峰与反相规则和 A1 一致。软件基线也使用符号加减、滚动能量和相同整数判决，并以 -O2 编译。二者均保存逐窗口统计，用于计时结束后的逐项比较和 CRC；比较/CRC、输入协议解析、串口收发不计入板内算法周期，电脑往返另列。

## MMIO

旧点积 `0x20000000` 接口保持。新扫描器基址 `0x20004000`，14 位偏移；仅接受对齐 32 位写入。SoC 每个被接受的事务只生成一次 access。

| 偏移 | 访问 | 含义 |
|---|---|---|
| 0x00 | W | 1 START；2 CLEAR：清错误、结果有效状态和帧装载计数，保留模板 |
| 0x04 | R | BUSY=1、DONE=2、ERROR=4 |
| 0x08 | RW | 帧长，START 时限制 64–1024 |
| 0x0c | R | 错误：1 长度；2 忙时写；3 未定义寄存器；4 写格式；5 未装载/顺序/结果索引；6 数值范围 |
| 0x10 | R | DONE 时窗口数量 N-63，否则 0 |
| 0x14 | R | 全部 64 个模板系数已装载为 1 |
| 0x18 | R | 核心周期；从 START 后到最后窗口提交，预期 66×(N-63) |
| 0x1c | R | 标识 0x57494e31，即 WIN1 |
| 0x20 | W | 结果索引；仅 DONE 且索引 < N-63 时接受 |
| 0x24 / 0x28 | R | 最近索引的有符号 S / 无符号 E，无有效索引时为 0 |
| 0x2c | R | 本帧成功写入样本数 |
| 0x30 / 0x34 | R | 复位以来成功模板写入数 / START 次数 |
| 0x1000+4i | W | 帧样本，低 16 位二补码；CLEAR 后必须按 0..N-1 顺序装载 |
| 0x2000+4i | W | 模板 i=0..63，仅允许 32 位 +1 或 -1 |

结果 BRAM 在接受索引写入的同一个时钟沿同步读取，下一次总线读事务可读取已锁存的 S/E；不使用异步 BRAM 读，也不需要软件延时。BUSY 时所有写操作拒绝并置错，正在进行的计算继续；错误保持到 CLEAR。START 要求帧数恰好等于长度、模板已完整加载且无先前错误。复位清全部控制和模板有效位，不清 BRAM 数组，重新装载后才能 START。

## UART

沿用 RVEC、版本 1、序号、长度与 CRC32，115200 8N1；全部整数为小端。命令 1 INFO、2 DOT 和响应布局不变。

- 命令 3 DETECT：`uint16 N, uint16 flags=0, int16 samples[N]`。越界样本报错误码 9，其余沿用旧协议错误。
- 命令 4 TRACE：`uint16 index, uint16 count`，count=1..64，范围须落在最近一次成功检测的窗口内。响应 0x84：相同 index/count，随后 count 组 `int32 S,uint32 E`。复位后或尚未成功检测时拒绝。非法请求不会抹除上一份成功结果；有效新检测开始后失效，成功时更新。
- DETECT 响应 0x83 固定 112 字节，下表均以 32 位字为单位。没有检测到目标的 position 为 0xffffffff；candidate 仍可用于诊断，全零无候选也为 0xffffffff。S 需解释为 int32。

| 字索引 | 含义 |
|---|---|
| 0–3 | N、窗口数、软件/硬件逐窗口不一致数、此次是否首次装载模板 |
| 4–8 | 软件 detected、position、candidate、S、E |
| 9–13 | 硬件 detected、position、candidate、S、E |
| 14–16 | 软件完整算法周期、硬件完整调用周期、硬件核心周期 |
| 17–19 | CLEAR/模板检查及装载阶段周期、帧拷贝周期、结果读取与选峰周期 |
| 20–21 | 软件和硬件逐窗口 S/E 的 CRC32，按窗口交织的小端字节计算 |
| 22–27 | 成功检测数、硬件状态、BUILD_ID、本帧写入数、累计模板写入数、累计 START 数 |

硬件完整调用包含模板阶段（包括首次装载）、整帧拷贝、配置/轮询、所有结果读取及 CPU 选峰；总周期不等于分段周期的简单和，还包含其间控制开销。CRC 不是唯一验证依据：固件逐窗口比较，TRACE 可让电脑逐值核对。


以上保留底层字段定义；A5 的命令与周期覆盖说明见 interface_a5.md。
