# A501 检测算法与接口

正式版本为 0000A501。PicoRV32 负责通信、调度和软件参考，FPGA 完成相关、能量及精确整数选峰。

## 固定算法

输入仍为 64–1024 个有符号样本，范围 −2048…2047，模板仍为冻结的 64 点 ±1 序列。归一化相关取绝对值，正反相均可检出。阈值固定 0.70，以 `100*S² >= 3136*E` 精确整数比较，能量为零不参与。

1. 在所有尚未排除的窗口中选最大 `S²/E`，用交叉乘法比较，完全相等时取最早位置。
2. 未达到阈值即停止；否则记录位置、S、E，排除起点差的绝对值小于 64 的窗口。
3. 最多返回四项，按每次选择顺序排列。超过四项只保留前四项；不声称能分离重叠目标，不用植入位置参与板上算法。

初次峰值与 A4 一样随扫描在线得到。额外扫描最多三遍已保存的 S/E BRAM，用同一个比较模块完成；不会重新搬运样本或模板。单目标命令保留。多目标核心计数为 `66*W+4+P*(6*W+1)`，W=N−63；实际额外遍数 P=min(3,检出数量)，零检出时为零。

## 接口

旧命令 1–7 保留，8 为多目标完整校验，9 为多目标运行。输入格式不变，板卡只收到 N 和样本。

多目标响应 224 字节：前 28 个 32 位字沿用 A4；字 28/29 为软件/硬件数量，30 为容量 4，31 保留 0；字 32–43 是四组软件 `(position,S,E)`，44–55 为硬件四组。未用槽位为 `(FFFFFFFF,0,0)`。运行模式的软件峰值、数量、列表、计时和 CRC 标记 FFFFFFFF，明确表示未执行。

新增 MMIO：0x50 多目标使能（写 0/1），0x54 数量；0x60 起每 12 字节一组 `(position,S,E)`，共四项。原 0x38–0x48 仍表示全帧首峰，不能被后续遍历覆盖。DONE 前结果不可见；BUSY 写入拒绝。CLEAR 清列表但保留模板，固件每帧显式配置模式。

## 命令与响应

| 命令 | 功能 | 响应载荷字节 |
|---|---|---:|
| 1 | INFO 与版本/计数 | 32 |
| 2 | DOT 点积软件/硬件对比 | 40 |
| 3 | 驻留扫描、CPU 判决 | 112 |
| 4 | TRACE 读取最近窗口统计 | 4+8×数量 |
| 5 | 兼容逐窗点积流程 | 112 |
| 6 / 7 | 硬件首峰校验 / 运行 | 112 |
| 8 / 9 | 最多四目标校验 / 运行 | 224 |

响应命令为请求命令加 0x80，错误为 0xff。基础线格式与 CRC 见 uart_protocol.md；命令 3 的前 28 字字段见 detection_interface.md，命令 5 的差异见 detection_a3_interface.md。最终字段顺序以 src/firmware/detection_a5.c 的 put32 和 src/host/detection_a5.py 的 verify 对照实现为准。

命令 6/7 的核心周期为 66×W+4；命令 3 保留 CPU 选峰。完整调用周期涵盖数据复制、启动、等待与结果读取，软件参考和 UART 往返分别计时。运行模式中的 FFFFFFFF 表示该项未执行，不能当成有效结果。
