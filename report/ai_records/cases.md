# FPGA 软硬件协同开发中的 AI 技术协作记录

以下分析六个工程问题的设计取舍、错误原因与验证结果。引述及 line 编号对应[交互原文摘录](dialogue.md)，失败日志与修复代码见[产物摘录](artifact_excerpts.json)。

AI 辅助覆盖 RTL、RISC-V 固件、主机参考、测试脚本、故障分析和结果整理；团队提供应用约束、板卡信息及实物接线、复位操作。工程路径以下均相对于项目根目录。

| C3 | 新命令返回值正确却被拒绝 | 修正响应类型，保留严格解析器 | 响应头前后代码、生产固件集成仿真 |

## C1 根据完整调用的分段测量调整软硬件划分

**技术任务。** 在 50 MHz PicoRV32 与 FPGA 加速器组成的系统中，降低 N=1024 扫描任务的完整调用开销，同时保持原有相关计算、阈值和并列峰规则。性能评价覆盖输入搬运、扫描、结果读取和判决。

**协作分析。** 初期逐窗口调用反复搬运重叠样本；将整帧与模板驻留后，仍需要 CPU 读取全部 S/E 统计并逐窗选峰。模型在 line_3172 根据实测指出，约 12.09 ms、即 86.6% 的完整调用时间消耗在读取和选峰。该观察确定了下一轮优化对象。line_2040、line_3179 保留方向选择，line_3208 明确保持检测规则和阈值。

**实现决策。** FPGA 在扫描时产生首峰，后续选峰复用已经保存的 S/E 统计，以整数交叉乘法比较归一化得分；CPU 保留通信、输入检查、调度与计时。完整校验模式返回逐窗口统计，运行模式返回最终结果，分别支持正确性核验和低通信开销演示。

| 测量版本和任务 | 路径 | 完整板内调用 |
|---|---|---:|
| A3 同一单目标输入 | 同板 CPU | 63.42896 ms |
| A3 同一单目标输入 | 旧逐窗口搬运 | 92.68054 ms |
| A3 同一单目标输入 | 数据驻留复用 | 13.95976 ms |
| A4 同一单目标输入 | 加速扫描后由 CPU 选峰 | 14.04242 ms |
| A4 同一单目标输入 | FPGA 选峰与判决 | 1.87052 ms |

**结论。** A4 同任务两条硬件路径相差约 7.51 倍，说明结果归约比继续增加算术并行度更值得优先处理。最终四报文应用的 41.51 倍属于另一组输入，单独统计。串口和网页时间也单独记录。

**证据。** board/results/baseline_a3/、board/results/baseline_a4/；原文 line_3172、line_3208、line_3286。

## C2 建立整数位宽契约并定位测试台超时截断

**技术任务。** 对 64 点 ±1 模板、12 位有符号样本，证明相关、能量、阈值和选峰比较在既定位宽内成立，并解释批量仿真为何在未完成输入时提前终止。

**数值推导。** 令 S=Σxᵢtᵢ，E=Σxᵢ²，xᵢ∈[-2048,2047]，tᵢ∈{-1,1}。因此 |S|≤64×2048=2^17，E≤64×2048²=2^28。比较两个窗口的 S²/E 时，交叉乘积满足 S₁²E₂≤2^62，能够由无符号 64 位整数表示；全零能量窗口单独排除。阈值采用 100S²≥3136E，避免浮点除法。相等得分保留较早位置，以便 CPU、RTL 和参考模型得到相同结果。

**发现的错误。** line_2328 记录批量仿真的超时常量位宽不足。原始日志显示 `FAIL: unit timeout`，停止时间为 1410065408 ns。该数值恰为 10^10 对 2^32 取模的结果，与预期长时限发生截断相符；它属于测试台终止条件问题，不能作为 RTL 算术不一致的证据。

**修正与验证。** 显式扩大测试超时表示位宽，重新执行同一批数据；同时核对滚动能量、BRAM 同步读延迟和 64 位比较路径。最终 A2 完成 3184 帧、3048498 个窗口的回归。合法输入范围由固件与硬件检查约束，传输采用 int16 并不意味着允许整个 int16 数值域。

**证据。** 原文 line_2289、line_2328；report/ai_records/evidence/a2_timeout.log；sim/results/detection_a2_unit.log；artifact_excerpts.json 中 a2_timeout。

## C3 用严格协议契约发现响应类型错误

**技术任务。** 为硬件判决增加命令后，确认命令号、响应类型、序号、长度、版本和 CRC 一致，使电脑端能够区分完整校验与运行模式。

**故障表现。** line_3300 记录：新命令返回时仍使用旧命令响应编号，被严格解析器拒绝。原固件 `response(command==5 ? 0x85 : 0x83,seq,body,112)` 只覆盖已有分支。新命令 0x06、0x07 因而返回 0x83，而协议要求分别为 0x86、0x87。

**修正决策。** 将响应类型生成改为 `response(command+0x80,seq,body,112)`，保留主机对命令和响应的严格对应检查。未执行的软件计算和逐窗核验字段使用 FFFFFFFF 标记，避免运行模式的空缺字段被误读为实测零值。

**验证顺序。** 重新编译生产固件 → 用实际 HEX 驱动 UART/CPU/MMIO 集成仿真 → 检查新旧命令及异常输入 → 重新构建配置文件 → 上板测量。line_3332、line_3381 对应修正后的回归和实现检查，A4 最终集成仿真覆盖 49 次事务。失败版本保存在快照中，未用于正式板测。

**证据。** report/ai_records/evidence/a4_old_header.c；report/ai_records/evidence/a4_corrected_header.c 第 315 行；artifact_excerpts.json 中 a4_old_header 与 a4_new_header。

## C4 从仿真到综合的语言模式与实现检查

**技术任务。** 实现最多四目标的贪心选峰：每轮选择最大归一化得分，抑制与已选起点距离小于 64 点的候选，保持固定阈值和确定性排序，并在 Vivado 2023.1 中完成综合实现。

**发现的错误。** 首轮 A5 的 .v 源码采用 `for(integer i=0;i<4;i=i+1)`。综合器按 Verilog 模式处理时报告 `Synth 8-10936: loop variable declaration is not allowed in this mode of Verilog`。错误发生在语言模式与声明位置，不是多目标判决规则本身。

**修正。** 将 `integer t, i;` 声明放到模块作用域，循环改为 `for(i=0;i<4;i=i+1)`。保持状态机、存储组织和排序规则，并使用修正版重新进行单元、固件集成及实现检查。

**验证结果。** 多目标扫描器通过 3487 帧、3249185 个窗口及 19 项错误检查；选峰器通过 1009 组；生产固件集成覆盖 94 次事务。最终占用 3935 LUT、2592 FF、19.5 BRAM36 等效和 13 DSP；50 MHz 下 WNS 9.468 ns、WHS 0.056 ns。普通 DRC 建议保留，无 Error/Critical Warning。

**证据。** 原文 line_3488、line_3532、line_3592、line_3720；report/ai_records/evidence/；src/rtl/window_multi_accel.v；sim/results/detection_a5_*；build/reports/riscv_0000a501/。

## C5 以版本与功能联合核对复位恢复和干净重建

**技术任务。** 检查物理复位能否清除运行状态，并确认独立目录重建的产物具有相同计算行为。验证同时覆盖源码来源、固件内容、正在运行的版本和实际输出。

**协作流程。** 关闭串口测试占用后执行 PL_RST，读取版本与计数，再运行已知输入及异常恢复序列。line_3992 保留物理按键确认，line_4056 记录计数归零、多目标计算恢复，以及干净重建后重新下载的恢复检查。

**可复现性判断。** 干净重建的 BIN/HEX 与冻结版逐字节相同；ELF 可能包含构建路径，需区分调试元数据差异和有效固件差异。独立生成的 bitstream 实际下载后，再检查 BUILD_ID 与计算结果。恢复批次分别对应物理按键和干净重建下载，两者不相互替代。

**版本边界。** A4 的恢复依据是仿真与重下载；A5 另有独立物理 PL_RST 和两组恢复批次。将每个 PASS 绑定到相应 build_id、输入与恢复条件，可避免把不同版本的通过记录合并使用。

**证据。** build/clean_a5_manifest.json；board/results/detection_a5_button_20260925_171123_025947/；board/results/detection_a5_clean_reprogram_20260925_171217_332944/；原文 line_3992、line_4056。

## C6 区分计算一致性与应用检出能力

**技术任务。** 将相关峰演示转化为可量化的短报文前导检测试验，检验系统在有正文、噪声、非目标信号和边界输入时的命中、漏检与误报。

**方案形成。** line_4194 提出加强应用验证；line_4269 将正常报文定义为 64 点前导与 128 点同幅随机正文，使正文与目标同样具有能量。先用 32＋32 个电脑样本检查方案，再固定正式数据集、算法版本和指标。line_4318、line_4367 对应测试前冻结，板卡只接收长度和样本，真值位置仅在电脑端评价时使用。

| 数据组成 | 块数 | 评价目的 |
|---|---:|---|
| 核心完整报文 | 480 | 随机位置、数量、幅度下的精确定位 |
| 非目标输入 | 1000 | 对正文、噪声及其他序列的误报 |
| 扰动输入 | 200 | SNR、直流偏置、强弱差异、单音与脉冲影响 |
| 边界输入 | 24 | 容量、重叠、相似序列及跨块限制 |

**结果。** 核心 1200/1200 个完整前导精确命中，1000 个常规非目标块无误报；扰动中存在漏检，相似序列边界产生 4 次额外输出。硬件与参考一致说明实现遵守算法，应用失败则说明算法或输入范围的边界，应分别报告。

**公平计时。** 另对同一四报文输入分别运行 30 次 CPU 与加速器调用，中位时间为 92.67158 ms 和 2.23240 ms，约 41.51 倍。串口完整校验往返约 327.923 ms，独立于板内加速比。未以重新调阈值或删除失败样本改善冻结数据表。

**证据。** data/application_preamble/；board/results/application_preamble_batch_20260925_174436_888233/；原文 line_4269、line_4279、line_4318、line_4367。

## 可复用的协作方法

每轮协作固定四项产物：输入及接口契约、待检验的技术假设、对应版本的修改、可重复执行的验收。发现故障时，先判断所属层次，再修正相应层并保留失败记录；通过后记录版本、输入、计时边界和文件清单。

本项目将这一方法落实到 skill/ 中的精确整数比对、文件核验和同任务计时脚本。独立点积与 FIR 夹具检验通用接口，故障注入检查拒绝能力，1704 个历史实板输入检验项目适配。适用范围及失败条件随技能包说明。
